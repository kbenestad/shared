TERMUX · PROOT · ALPINE · POSTMARKETOS

Phosh on your phone, without flashing anything

A step-by-step build of postmarketOS's Phosh interface inside a Termux proot container — adapted from Ivon Huang's guide, with the gaps filled in.

Base guide: ivonblog.com · This version fills in the missing visudo and editor-save steps.

SET YOUR VERSIONS

Every command, URL and config file below rewrites itself to match — including what the Copy buttons put on your clipboard. The two versions are not independent: each postmarketOS release is built against one specific Alpine release, and mixing them will make apk fail to resolve packages. The current pairing is listed in postmarketOS's own channels.cfg — find your release and use its mirrordir_alpine value as the Alpine version.

Read this first. This is not real postmarketOS — it's Alpine Linux running in an unprivileged proot container, converted to use pmOS repositories and packages. There's no direct hardware access, no kernel-level power management, and Phosh is a Wayland compositor nested awkwardly inside X11. Expect roughness: the source guide itself notes Phosh may only launch reliably once or twice per session.

BEFORE YOU START

Prerequisites

Install these Android apps from F-Droid or their official sources first — not the Play Store versions, which are outdated:

Termux · Termux:X11 · Hacker's Keyboard, for a real keyboard layout when typing into the desktop.

Termux:X11 is two separate pieces. The app you just installed is only the X server — the window that eventually displays the desktop. The termux-x11 command that talks to it lives in a separate Termux package, which is not installed by default and does not come from Termux's standard repository. Step 1 installs it. Miss this and step 10.2 fails with termux-x11: command not found.
STEP 1

Install proot Alpine Linux

Run these in Termux, one line at a time:

termux 
pkg update
pkg install proot-distro pulseaudio
proot-distro install alpine

Now add the X11 packages. These are not in Termux's default repository — x11-repo is a small package whose only job is to register that extra repository, so it has to go in first and be followed by a pkg update before the other two are visible:

termux 
pkg install x11-repo
pkg update
pkg install termux-x11-nightly virglrenderer-android

termux-x11-nightly provides the termux-x11 command used in step 10.2. virglrenderer-android provides virgl_test_server_android used in step 10.3, which offers the container a path to the GPU for OpenGL. Install it — step 10.3 fails without it — but do not expect hardware acceleration of the desktop itself: the compositor cannot get a DRM file descriptor through the X server and falls back to CPU rendering regardless. Individual GL applications inside the session may still benefit.

STEP 2

Switch Alpine's repo from Edge to v3.24

Edge is Alpine's rolling/unstable branch. Log in and edit the repo file:

termux 
proot-distro login alpine --shared-tmp
apk update
apk add nano

Then open the repo file:

inside alpine 
nano /etc/apk/repositories

Inside nano: use the arrow keys to edit directly (no mode switching needed), change every line that says edge to v3.24 (e.g. .../alpine/edge/main → .../alpine/v3.24/main), then press Ctrl+O then Enter to save, and Ctrl+X to exit.

Now update:

inside alpine 
apk update
apk upgrade
STEP 3

Create a user and grant sudo access

Create the account:

inside alpine 
apk add sudo
addgroup storage
adduser -g wheel,storage,video,audio user

You'll be prompted to set a password for user — type one and confirm it.

The gap in the original guide: it tells you to run visudo but never says what to type. Here's exactly what goes in the file and how to save it.

visudo opens whatever editor the EDITOR variable points to — on Alpine that's vi by default, not nano. Install nano and point visudo at it first:

inside alpine 
apk add nano
export EDITOR=nano
visudo

This opens /etc/sudoers in nano. Add this line at the very bottom of the file — it lets your new user run sudo without typing a password every time, since this container only you can access:

add to sudoers 
user ALL=(ALL) NOPASSWD: ALL

Prefer to keep a password prompt on sudo? Use user ALL=(ALL) ALL instead. Either works with the rest of this guide — the passwordless version is just less friction inside a container nobody else can reach.

SAVING IN NANO

  1. Use arrow keys to reach the last line
  2. Type the sudoers line above
  3. Press Ctrl+O then Enter to write out
  4. Press Ctrl+X to exit

The export EDITOR=nano only lasts for this terminal session. If you open a new Termux session later and run visudo again, you'll need to set it again first — or it'll fall back to vi.

STEP 4

Set the timezone

Replace Asia/Taipei with your own zone if different (list at /usr/share/zoneinfo):

inside alpine 
sudo ln -sf /usr/share/zoneinfo/Asia/Taipei /etc/localtime
sudo setup-timezone
STEP 5 · OPTIONAL

Enable SSH into the container

Useful if you'd rather type on a real keyboard over the network. Skip this if you don't need it.

inside alpine 
sudo nano /etc/ssh/sshd_config

Find the line starting with Port and change 22 to 8023 (regular Termux, outside proot, may already use port 22). Save with Ctrl+O, Enter, then exit with Ctrl+X.

inside alpine 
ssh-keygen -A
rc-update add sshd
rc-service sshd start
ip addr

The last command prints your phone's IP address — you'll need it to connect. Note: rc-service, not the guide's typo rc-serive.

STEP 6

Add the postmarketOS repository

inside alpine 
nano /etc/apk/repositories

Add this line at the very top of the file:

add to repositories 
https://mirror.postmarketos.org/postmarketos/v26.06

This URL uses whatever you typed in the box at the top of the page. If a newer pmOS release has shipped since, change it there once and every step updates.

STEP 7

Trust postmarketOS's package signing keys

inside alpine 
apk add -u --allow-untrusted postmarketos-keys
apk update && apk upgrade
STEP 8

Set the system identity

Open the file:

inside alpine 
sudo nano /etc/os-release

Select all existing lines and delete them (in nano: Ctrl+Shift+6 or Alt+A to start a selection, arrow down to the end, then Ctrl+K to cut — or just hold Backspace/Delete until the file is empty), then type in:

/etc/os-release 
PRETTY_NAME="postmarketOS v26.06"
NAME="postmarketOS"
VERSION_ID="v26.06"
VERSION="v26.06"
ID="postmarketos"
ID_LIKE="alpine"
HOME_URL="https://www.postmarketos.org/"
SUPPORT_URL="https://gitlab.com/postmarketOS"
BUG_REPORT_URL="https://gitlab.com/postmarketOS/pmaports/issues"
LOGO="postmarketos-logo"

Then save with Ctrl+O, Enter, and exit with Ctrl+X.

STEP 9

Install Openbox, Cage, and Phosh

inside alpine 
sudo apk add openbox cage
inside alpine 
sudo apk add postmarketos-ui-phosh \
postmarketos-tweaks \
firefox \
mobile-config-firefox \
font-noto \
font-noto-cjk \
font-noto-cjk-extra \
font-noto-emoji

This is a large install — give it time on a slower connection.

STEP 10

Launch everything

Each of these runs in order. Steps 1–3 happen in plain Termux, before logging into Alpine.

10.1 — Start PulseAudio (Termux):

termux 
pulseaudio --start --exit-idle-time=-1
pacmd load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1 auth-anonymous=1

10.2 — Start Termux:X11 (Termux):

termux 
export DISPLAY=:0
termux-x11 :0 &

This should open the Termux:X11 app automatically. If it doesn't, open it manually from your app drawer.

10.3 — Start the virglrenderer server (Termux):

termux 
virgl_test_server_android &

10.4 — Log into Alpine as your user:

termux 
proot-distro login alpine --user user --shared-tmp

10.5 — Launch Openbox, Cage, and Phosh (inside Alpine):

inside alpine 
export DISPLAY=:0
export XDG_RUNTIME_DIR=/tmp
openbox &
cage -- phoc -S -C /usr/share/phosh/phoc.ini -E /usr/libexec/phosh &
This command differs from the original guide. The guide ends it with -U, which phoc does not accept — and an unrecognised option makes phoc print Unknown option -U and exit immediately, so Phosh never starts. The flags above are the ones upstream's own phosh-session script uses: -S puts phoc in shell mode so Phosh can attach to it, and -C points at the config file that ships with the phosh package. The -- makes explicit that everything after it is for phoc, not for cage.

Do not substitute phosh-session for this command, even though that is the normal way to start Phosh on real hardware. It forces WLR_BACKENDS=drm,libinput, which needs direct access to the display and input hardware — exactly what an unprivileged proot container does not have.

STEP 11

Fit the display to your screen

Switch to the Termux:X11 app. An Openbox window frame should appear — double-tap its title bar to maximize it.

Pull down your phone's notification shade, tap the Termux:X11 notification's preferences, and set:

Output → Scaled (fits Phosh to your screen size)  ·  Pointer → Direct Touch (makes your screen taps register as touch, not a mouse cursor)

If Phosh doesn't come up, or only worked once: this is a known, currently-unresolved issue with this setup, not something you did wrong. Killing the cage process and re-running step 10.5 is the usual first thing to try.

Reading the startup log

Step 10.5 prints a wall of warnings even when it works. These lines are all expected in a proot container and are not why something failed:

harmless 
Failed to open DRI3
Failed to query DRI3 DRM FD
Disabling DMA-BUF support
drmGetDevices2 failed: Permission denied
Creating pixman renderer
Failed to create wlr_drm_lease_manager_v1
X11 error: op 18:0, code 5

They all say the same thing in different words: there is no direct access to the GPU or display hardware from inside an unprivileged container, so rendering falls back to pixman, which draws on the CPU. That is the expected outcome here, and Phosh is still usable at phone resolution. Seeing Mapping input device x11-pointer and x11-touch means input is working.

The line that actually matters is anything ending in the compositor exiting — for example phoc-WARNING **: Unknown option, which means a flag in your launch command is wrong and phoc quit before starting.
