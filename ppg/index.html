TERMUX · PROOT · DEBIAN · XFCE

A Debian desktop on your Android phone

Start to finish, from a freshly installed Termux. No root, no unlocked bootloader, nothing flashed. Copy each block in order and you get a working XFCE desktop with real desktop applications.

What this actually is. A Debian userland running under proot — an unprivileged emulation layer — drawing onto an X server that runs as an ordinary Android app. It is a real Debian with real apt, and it is genuinely useful for desktop applications on the move. It is not a phone operating system, and it has no access to your GPU: everything draws on the CPU. Expect a capable, slightly slow desktop, not a replacement for a laptop.

BEFORE YOU START

Two apps, and not from the Play Store

You need two Android apps. Do not install either from the Play Store — those builds are years out of date and will not work with these instructions. Get both from F-Droid or from each project's own GitHub releases page:

Termux — the terminal everything runs in.
Termux:X11 — the window your desktop appears in.

A third is optional but makes life much easier: Hacker's Keyboard, which gives you Ctrl, Tab, Escape and arrow keys. You will want those.

Install both apps from the same source. Termux and Termux:X11 have to be signed by the same key to talk to each other. Two from F-Droid, or two from GitHub — never one of each. This is the single most common reason a setup fails at the last step.
STEP 1

Set up Termux

Open Termux. Everything in this step is typed there. First bring it up to date — this alone can take a few minutes:

termux 
pkg upgrade -y

If it asks about replacing configuration files, pressing Enter to accept the default is fine.

Now give Termux permission to reach your phone's own files. Android will pop up a permission dialog — allow it:

termux 
termux-setup-storage

Skip this and your Downloads, Photos and Documents folders will not be visible from the desktop later.

STEP 2

Install the X server and sound

The X11 packages live in a separate repository that is not enabled by default. x11-repo is a tiny package whose only job is to switch that repository on, so it has to go in first and be followed by an update before anything else becomes visible:

termux 
pkg install -y x11-repo
pkg update

Now the rest:

termux 
pkg install -y termux-x11-nightly pulseaudio proot-distro

termux-x11-nightly is the command that talks to the Termux:X11 app you installed — the app on its own is not enough. pulseaudio carries sound out of the container. proot-distro installs and runs Debian.

STEP 3

Install Debian

termux 
proot-distro install debian:trixie

This downloads a few hundred megabytes. Leave it alone until it finishes.

The :trixie part pins the Debian release (Debian 13). Without it you get whatever latest points at today, which will silently become a different Debian at some point in the future and quietly invalidate the rest of this page. Pinning costs nothing and means these instructions keep working.

STEP 4

Install the XFCE desktop

Step into Debian. Your prompt changes to show you are inside it:

termux 
proot-distro login debian

Now install the desktop. This is the big download — several hundred megabytes, and slow on a phone. Start it and go and do something else:

inside debian 
apt update
apt install -y xfce4 xfce4-terminal xfce4-whiskermenu-plugin \
  dbus-x11 librsvg2-common adwaita-icon-theme \
  fonts-noto-core fonts-dejavu \
  mousepad xfce4-taskmanager thunar-archive-plugin

Set up a language so applications stop complaining about a missing locale:

inside debian 
apt install -y locales
sed -i 's/^# *en_US.UTF-8/en_US.UTF-8/' /etc/locale.gen
locale-gen

Then leave Debian and go back to Termux:

inside debian 
exit
Why there is no "create a user" step. Most guides have you add a normal user and set up sudo. Here you stay as root inside the container, deliberately. Root in proot is not root on your phone — every process still runs as the ordinary, unprivileged Android user that Termux itself runs as, confined to Termux's own sandbox. Adding a user buys you no real isolation, and it adds a sudoers step that is the most common place these setups break. If you later want a normal user for its own sake, you can add one at any time.
STEP 5

Make one command that starts everything

Starting the desktop by hand means five commands in the right order, every time. Instead, write them into a script once. Paste this whole block into Termux exactly as it is — it creates the file and makes it runnable:

termux 
cat > ~/desktop <<'EOF'
#!/data/data/com.termux/files/usr/bin/bash

# Clear out anything left running from a previous session
pkill -f termux-x11 >/dev/null 2>&1
proot-distro kill debian >/dev/null 2>&1

# Sound
pulseaudio --start --exit-idle-time=-1 >/dev/null 2>&1
pacmd load-module module-native-protocol-tcp \
  auth-ip-acl=127.0.0.1 auth-anonymous=1 >/dev/null 2>&1

# X server
export DISPLAY=:0
termux-x11 :0 >/dev/null 2>&1 &

# Wait for the X server to actually be ready, rather than guessing
for i in $(seq 1 20); do
  [ -e "$TMPDIR/.X11-unix/X0" ] && break
  sleep 0.5
done

# Start the desktop
proot-distro login debian --shared-tmp --shared-x11 \
  -e DISPLAY=:0 \
  -e PULSE_SERVER=127.0.0.1 \
  -e XDG_RUNTIME_DIR=/tmp \
  -- dbus-run-session startxfce4
EOF
chmod +x ~/desktop

From now on, ~/desktop is the only command you need. It cleans up after any previous run first, which is what stops the second launch of the day from failing.

STEP 6

First launch

termux 
~/desktop

The Termux:X11 app should come to the front by itself. If it does not, open it from your app drawer — the desktop is already running behind it.

The first start is the slowest; XFCE is building its caches. Give it a minute before deciding something is wrong.

Set the display up for a phone

In the Termux:X11 app, pull down your notification shade, tap the Termux:X11 notification, and set:

Output → Scaled  ·  Pointer → Direct Touch

Direct Touch is the important one: it makes your taps land where you touch instead of dragging a mouse cursor around.

STEP 7

Make it usable with fingers

Out of the box XFCE is built for a mouse on a large screen, and on a phone the controls are far too small to hit. This fixes that.

Open Terminal inside the XFCE desktop — not Termux. These settings are applied through the running desktop session, so they will not work from a Termux prompt. Use the Whisker Menu, or right-click the desktop and choose Open Terminal Here. Then paste:

inside the xfce desktop 
# Size — the single biggest improvement
xfconf-query -c xsettings -p /Gdk/WindowScalingFactor -n -t int -s 2
xfconf-query -c xsettings -p /Xft/DPI -n -t int -s 96
xfconf-query -c xsettings -p /Gtk/CursorThemeSize -n -t int -s 32

# Stop a slightly wobbly tap being read as a drag
xfconf-query -c xsettings -p /Net/DndDragThreshold -n -t int -s 24
xfconf-query -c xsettings -p /Net/DoubleClickTime -n -t int -s 500

# Appearance
xfconf-query -c xsettings -p /Net/IconThemeName -n -t string -s "Adwaita"
xfconf-query -c xsettings -p /Gtk/DialogsUseHeader -n -t bool -s true

# No compositing: there is no GPU here, and it only costs speed
xfconf-query -c xfwm4 -p /general/use_compositing -n -t bool -s false

# Title bars you can grab, and only two buttons to mis-tap
xfconf-query -c xfwm4 -p /general/title_font -n -t string -s "Sans Bold 12"
xfconf-query -c xfwm4 -p /general/button_layout -n -t string -s "|MC"

# One tap opens a file
xfconf-query -c thunar -p /misc-single-click -n -t bool -s true

# A panel you can actually hit
xfconf-query -c xfce4-panel -p /panels/panel-1/size -n -t int -s 48

Close the desktop and start it again with ~/desktop for the scaling to take effect.

If everything now looks too big, set /Gdk/WindowScalingFactor back to 1 and raise /Xft/DPI to 144 instead — that enlarges text without doubling every control. If the panel line does not take, set it by hand: right-click the panel → Panel → Panel Preferences → Row Size.

Add a searchable menu

The default XFCE menu is a nest of submenus, which is miserable on a touchscreen. Right-click the panel → Panel → Add New Items → Whisker Menu. It gives you a search box, which is the part of a modern desktop menu you actually use.

STEP 8

Day-to-day use

Starting and stopping

Start it with ~/desktop in Termux. To shut it down cleanly, log out from inside XFCE, or from a Termux prompt:

termux 
proot-distro kill debian
pkill -f termux-x11

Leaving the desktop running in the background costs battery. Shut it down when you are finished rather than just switching away.

Installing applications

Anything in Debian, from a terminal inside the desktop or from proot-distro login debian:

inside debian 
apt install -y firefox-esr

Heavy applications will run, slowly. A browser and an office suite are usable for real work; video editing and 3D are not, because there is no GPU here.

Your phone's files

Your Android storage is visible inside the desktop at /sdcard. Open Thunar and type that path to reach Downloads, Documents and Pictures — files you save there are visible to your normal Android apps, and vice versa.

Typing

Use your normal Android keyboard; it types into the desktop. Hacker's Keyboard is worth switching to whenever you need Ctrl, Esc, Tab or arrow keys, which is most of the time in a desktop application.

STEP 9

When something goes wrong

The screen is black, or nothing appears

Open the Termux:X11 app from your app drawer. The desktop is usually running fine; the window just did not come to the front.

"cannot open display"

The X server was not ready. Press Ctrl+C in Termux and run ~/desktop again — it clears up the half-started session before retrying.

It worked yesterday and not today

Almost always a leftover process from the previous run. ~/desktop already clears those out at the start, so run it a second time before assuming anything is broken. If that fails, close Termux entirely (swipe it away from your recent apps) and start again.

No sound

Sound only starts when ~/desktop does. If you logged into Debian by hand rather than using the script, there is no audio; exit and use the script.

Warnings in the terminal

A running desktop prints a great deal of noise — missing metadata files, D-Bus messages, complaints about sensors and power management that a phone container does not have. None of it means anything is wrong. The only messages worth reading are ones followed by the desktop actually disappearing.

Things that will not work, no matter what you try. There is no access to your GPU, so everything renders on the CPU. There is no access to raw input devices, so multi-touch gesture tools such as touchegg cannot function. There is no real init system, so anything expecting systemd will not start. These are consequences of running unprivileged on a locked phone, not of anything you have done wrong, and no amount of configuration changes them.
