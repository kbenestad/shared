FLUXLINUX · DEBIAN · XFCE · ANDROID

Turning a desktop into something you can use with your thumbs

Picking up where FluxLinux leaves off: window behaviour, screen space and control sizes for a 6-inch display, then the applications that make it worth carrying.

What this assumes. You already have FluxLinux installed with a Debian container running XFCE, and you can open a terminal inside that desktop. This is not an installation guide — it starts at the point where you have a working but awkward desktop, and makes it pleasant. Everything below runs inside the Debian container, as root, unless it says otherwise.
There is a script for all of this. Everything below is also an interactive script you can run inside the container. It asks before each part, skips what it cannot do, and is safe to run more than once — any file it replaces is backed up alongside the original with a .bak suffix.
inside debian 
wget https://kbenestad.github.io/shared/desk/setup.sh
less setup.sh
bash setup.sh

The middle line is not decoration. Read a script before you run it — especially one that installs packages as root. Press q to leave less. Run it from a terminal inside the running desktop: the appearance settings talk to the live session, so a plain container login shell cannot apply them. It will tell you if that is the case rather than failing quietly.

Everything the script does is written out step by step below, so you can do any of it by hand instead, or understand what the script changed.

STEP 1

Windows that open maximised

On a phone screen there is no such thing as a useful floating window. XFCE has no setting for this, so it takes a small helper: devilspie2 watches for new windows and acts on them.

inside debian 
apt update
apt install -y devilspie2

Give it one rule. Normal windows get maximised; dialogs, menus and popups are left alone, which matters — maximising a file-picker dialog is worse than useless:

inside debian 
mkdir -p ~/.config/devilspie2
cat > ~/.config/devilspie2/maximise.lua <<'EOF'
if (get_window_type() == "WINDOW_TYPE_NORMAL") then
   maximize()
end
EOF

Start it with the desktop, every time:

inside debian 
mkdir -p ~/.config/autostart
cat > ~/.config/autostart/devilspie2.desktop <<'EOF'
[Desktop Entry]
Type=Application
Name=devilspie2
Exec=devilspie2
X-GNOME-Autostart-enabled=true
EOF
devilspie2 &

The last line starts it now so you can test without restarting. Open something — it should fill the screen.

Prefer true fullscreen, with the panel hidden too? Replace maximize() with set_window_fullscreen(true). On a phone that is usually the wrong trade: you lose the panel, and with it the only easy way to switch between applications.

STEP 2

Reclaim the wasted edges

A maximised window still wears a title bar and a border it has no use for — there is nothing to drag it to. XFCE can drop both:

inside debian 
xfconf-query -c xfwm4 -p /general/titleless_maximize -n -t bool -s true
xfconf-query -c xfwm4 -p /general/borderless_maximize -n -t bool -s true
xfconf-query -c xfwm4 -p /general/use_compositing -n -t bool -s false

That recovers roughly 40 vertical pixels per window and, with compositing off, a noticeable amount of speed. There is no GPU doing the compositing here, so it costs you nothing to switch off.

The panel can get out of the way too, appearing when you reach for the screen edge:

inside debian 
xfconf-query -c xfce4-panel -p /panels/panel-1/autohide-behavior -n -t int -s 1

If that behaves oddly, set it in the GUI instead: right-click the panel → Panel → Panel Preferences → Automatically hide the panel.

And the row of keys at the bottom of Termux

Termux draws two rows of extra keys that eat screen height. You do not have to configure anything to be rid of them — there is a built-in toggle:

Volume Up + Q hides and shows the extra keys row. (Volume Up + K does the same thing.)

To remove them permanently instead, in Termux, not the container:

termux 
mkdir -p ~/.termux
echo "extra-keys = [[]]" >> ~/.termux/termux.properties
termux-reload-settings

Try the keypress first. You will want those keys back the moment you do terminal work rather than desktop work, and a keypress is easier to undo than a config file.

STEP 3

Size the controls for fingers

Do not use XFCE's display scaling. It is integer-only — 1× or 2×, with nothing in between. 2× is a blunt doubling that looks crude and throws away the screen you paid for. This is the real difference you noticed against Plasma, which has proper fractional scaling. XFCE cannot do that, so do not ask it to.

Instead, scale the chrome and leave the content alone. A 6.4-inch 1080×2400 screen is about 16 pixels per millimetre. A default 36-pixel panel is roughly 2 mm tall; a fingertip needs 7–9 mm. Menus, panels and title bars have to grow. Documents and web pages do not — those have their own zoom, and you can read them perfectly well at full density.

inside debian 
# Interface text — affects menus, buttons and dialogs, not documents
xfconf-query -c xsettings -p /Gtk/FontName -n -t string -s "Sans 13"

# A panel you can actually hit: 96px is about 6mm
xfconf-query -c xfce4-panel -p /panels/panel-1/size -n -t int -s 96

# For the windows that do still show a title bar
xfconf-query -c xfwm4 -p /general/title_font -n -t string -s "Sans Bold 15"
xfconf-query -c xfwm4 -p /general/button_layout -n -t string -s "|MC"

# Stop a slightly wobbly tap registering as a drag
xfconf-query -c xsettings -p /Net/DndDragThreshold -n -t int -s 24
xfconf-query -c xsettings -p /Net/DoubleClickTime -n -t int -s 500

# One tap opens a file
xfconf-query -c thunar -p /misc-single-click -n -t bool -s true

# Bigger pointer, for when you do use a mouse
xfconf-query -c xsettings -p /Gtk/CursorThemeSize -n -t int -s 32

If you change one thing on this page, make it DndDragThreshold. The default is 8 pixels — half a millimetre here. Every slightly imprecise tap becomes an accidental drag, and the desktop feels broken rather than merely small.

button_layout of "|MC" leaves only maximise and close on the right. Fewer, larger targets, and no more closing a window when you meant to minimise it.

Finally, in the Termux:X11 notification preferences, set Pointer → Direct Touch. That is what turns your finger into a finger rather than a trackpad.

STEP 4

Browsers

Epiphany — the one that actually fits

inside debian 
apt install -y epiphany-browser

GNOME Web. It is built with libadwaita, which means its interface genuinely reflows for narrow screens rather than shrinking — it is the browser used on Linux phones. Light, and the best-behaved of the three on a display this size.

Vivaldi — for when you need a full browser

inside debian 
apt install -y wget gnupg
wget -qO- https://repo.vivaldi.com/archive/linux_signing_key.pub \
  | gpg --dearmor -o /usr/share/keyrings/vivaldi.gpg
echo "deb [signed-by=/usr/share/keyrings/vivaldi.gpg arch=arm64] \
https://repo.vivaldi.com/archive/deb/ stable main" \
  > /etc/apt/sources.list.d/vivaldi.list
apt update
apt install -y vivaldi-stable

Vivaldi does publish arm64 builds, despite its repository's Release file listing only amd64 — the arm64 index is populated and current. About 450 MB installed. It is a heavy browser on a device with no graphics acceleration; keep Epiphany for everyday reading and reach for this when a site demands it.

Firefox ESR and Chromium are both in Debian if you would rather: apt install -y firefox-esr.

STEP 5

OnlyOffice

Not in Debian, and not available as a Flatpak you can use — see the note below. Install the arm64 package directly:

inside debian 
apt install -y wget
wget https://download.onlyoffice.com/install/desktop/editors/linux/onlyoffice-desktopeditors_arm64.deb
apt install -y ./onlyoffice-desktopeditors_arm64.deb
rm onlyoffice-desktopeditors_arm64.deb

Using apt install ./file.deb rather than dpkg -i pulls in its dependencies automatically. They are all ordinary Debian packages — GTK3, Cairo, ALSA, GStreamer, fonts — with nothing that a container cannot provide. Budget about 1.3 GB installed on top of the download.

Do not try the Flatpak. Flatpak depends on bubblewrap, and bubblewrap needs unprivileged user namespaces, which proot cannot provide. Every Flatpak application fails the same way, and it is not something a workaround can patch around — sandboxing is the whole of what Flatpak does. This applies to any Flatpak in a proot container, not just this one.
STEP 6

GNOME apps that suit a small screen

This is a better idea than it first sounds. Modern GNOME applications are built with libadwaita, which was designed for Linux phones — they collapse to a single column on a narrow window instead of becoming a cramped desktop layout. They are the most touch-appropriate software you can put on this desktop, and they run perfectly well under XFCE.

inside debian 
apt install -y gnome-console nautilus gnome-calculator \
  gnome-weather gnome-maps gnome-clocks \
  gnome-text-editor gnome-contacts gnome-calendar
gnome-consoleKGX. Clean, touch-friendly terminal.
nautilusFiles. Adaptive, and far nicer than Thunar with a finger.
gnome-calculatorIncludes currency conversion — switch mode from the hamburger menu.
gnome-weatherSet your city by hand; see the note below.
gnome-mapsWorks, but search and routing need a connection.
gnome-clocksWorld clocks, timers, alarms.
gnome-text-editorLight, adaptive, good for notes.
gnome-contacts, gnome-calendarUseful if you connect an account.
These need one environment variable to be quick. GNOME apps use GTK4, which renders through OpenGL by default. There is no GPU here, so that path goes through software emulation and feels terrible. GTK4 accepts a plain software renderer instead, and it is markedly faster for this kind of interface.
inside debian 
echo 'export GSK_RENDERER=cairo' >> ~/.profile

Restart the desktop, then check it took effect — open a terminal inside the session and run:

inside the desktop 
echo $GSK_RENDERER

If that prints nothing, FluxLinux is starting the session without reading ~/.profile. You can still get the benefit per-application by launching with the variable inline, for example GSK_RENDERER=cairo nautilus, or by adding it to each application's launcher command.

Location services do not exist in a container, so Weather and Maps cannot find you. Set your location by hand once and they behave normally after that.

STEP 7

What to expect

Restart the desktop so everything above takes effect together. What you should have: applications that open filling the screen with no title bar, a panel you can hit that stays out of the way, taps that do not turn into drags, and a set of applications that were designed for a screen this shape.

What will still be true:

Software renderingNo GPU acceleration is configured. Everything draws on the CPU, so heavy applications start slowly and scroll imperfectly.
No gesture supportMulti-touch gesture daemons such as touchegg read raw input devices, which a container cannot reach. Direct Touch gives you taps and drags, not swipes.
No Flatpak, no SnapBoth need facilities proot has no way to provide.
No location, no sensorsAnything expecting GPS, rotation or ambient light will fall back or fail quietly.

Two of the settings here are worth revisiting once you have lived with it: the panel size, and the interface font. They are the two that trade screen space against reachability, and the right answer depends on whether you are mostly reading or mostly tapping.

Written for a Nokia X30 — 1080×2400 at about 409 ppi — running FluxLinux with a Debian container and XFCE 4.20. Every package name, configuration property and command here was checked against the shipped packages rather than written from memory. A companion guide that builds the same thing by hand, without FluxLinux, is at /ppg.
